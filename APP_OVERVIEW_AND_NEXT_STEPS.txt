We Two — App Functionality Overview & Next Steps
Date: 2026-04-07

============================================================
1) WHAT THE APP CURRENTLY DOES
============================================================

A) App startup and backend connection
- On launch, the app loads env vars from .env:
  - SUPABASE_URL
  - SUPABASE_ANON_KEY
- If missing, startup throws a clear exception.
- Supabase is initialized before the app UI starts.

B) Authentication flow
- Auth screen supports:
  - Login (email + password)
  - Sign up (email + password + username)
- Sign-up sends username through metadata so backend trigger can create profile data.
- Auth errors are mapped to user-friendly messages (invalid credentials, email not confirmed, etc.).

C) Mandatory profile setup gate
- After authentication, app checks profile completeness.
- If first_name is missing/empty, user is forced to /profile_setup.
- Profile setup includes:
  - Avatar pick from gallery
  - First name (required)
  - Last name (optional)
  - Birthday picker
- On submit:
  - Optional avatar upload to Supabase Storage bucket `avatars`
  - Profile data upsert in `profiles`
  - Auth gate refresh
  - Redirect to /chat when profile is complete

D) Main chat entry behavior
- /chat now opens FindPartnerScreen (entry controller).
- If user has no active partner, app shows:
  - “add people to start chatting”
  - “Find People” button to open discovery
- If active partner exists, app opens the direct chat screen.

E) Direct chat behavior
- Real-time message stream shown for the active duo.
- Input field sends message to `messages` table.
- Send button has loading state and guarded execution.
- If sending fails, snackbar feedback is shown.
- Contact switching is still available through contacts sheet.

F) People & Discovery feature
- Discovery screen includes:
  - Search input (fuzzy, case-insensitive): ilike('username', '%query%')
  - Requests button with red badge (unseen requests)
  - Result cards with avatar, username, and person_add action
- Request bottom sheet shows pending requests with:
  - Accept
  - Decline

G) Request handling
- Sending request uses RPC: send_partner_request.
- Responding to request now uses:
  1) Preferred RPC path: respond_partner_request (if exists)
  2) Fallback client-side transactional-ish updates:
     - validate ownership
     - update request status
     - on accept: set active_partner_id for both users

H) Routing and guards
- Route behavior:
  - /setup if backend config is unavailable
  - /auth when unauthenticated
  - /profile_setup when profile incomplete
  - /chat when authenticated and profile complete
  - /discovery for people search and requests

============================================================
2) HOW TO USE THE APP (CURRENT USER JOURNEY)
============================================================

1. Add SUPABASE_URL and SUPABASE_ANON_KEY in .env.
2. Launch app.
3. Sign up or log in.
4. If prompted, complete profile setup.
5. Land on /chat:
   - If no active duo: tap “Find People”
   - Search users by username
   - Send request
6. Open Requests modal and accept a request.
7. Duo becomes active; app enters direct chat screen.
8. Exchange messages in real time.

============================================================
4) KNOWN LIMITATIONS / RISKS RIGHT NOW
============================================================

1. Message stream filtering still relies on client-side filtering from a full stream.
   - This can become costly and should be moved server-side with strict RLS and/or RPC.

2. Contact source depends on accepted requests + active partner.
   - Good improvement, but should be fully normalized around one relationship source of truth.

3. Request response fallback path is not fully atomic.
   - Preferred production path is a single DB RPC transaction.

4. Discovery currently assumes table/columns:
   - partner_requests(status, is_seen, from_user_id, to_user_id, created_at)
   - If schema differs, behavior may degrade.

5. Chat header still surfaces partner ID in some paths.
   - Should use display name/avatar from profile.
